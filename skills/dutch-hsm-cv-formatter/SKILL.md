# 🇳🇱 Dutch HSM CV Formatter (`dutch-hsm-cv-formatter`)

The `dutch-hsm-cv-formatter` skill converts raw project histories, freelance consulting, and technical deliverables into rigorous, honest engineering case studies optimized for the Dutch tech recruitment market and High Skilled Migrant (HSM) visa sponsorship.

It targets senior hands-on roles (**Senior Full-Stack Engineer | Systems Architecture**) where candidates are valued for both immediate production delivery and high-level architectural ownership.

---

## 🛑 Scope Boundaries (Do's & Don'ts)

### ✅ Do's
1. **Technical Honesty (*Nuchterheid*)**: State technologies accurately (PHP, WordPress, TypeScript, Node.js, React, MySQL, Docker). Never obfuscate real tools behind corporate jargon.
2. **Architectural Depth**: Highlight architectural decisions, schema design, caching layers (Redis), API decoupling, and CI/CD pipelines within full-stack execution.
3. **Quantifiable Metrics**: Prioritize empirical metrics (e.g., latency reduction, throughput, query optimization, uptime) whenever supported by source data.
4. **HSM Tier Alignment**: Frame accomplishments to support the €75,000–€90,000+ Dutch HSM compensation tier.

### ❌ Don'ts
1. **No Title Inflation**: Do not label hands-on full-stack roles as detached "Enterprise Architect" or "Executive Director".
2. **No Technology Obfuscation**: Never hide WordPress or PHP behind euphemisms like "Block-Native Ecosystem".
3. **No Fluff or Buzzwords**: Ban empty adjectives ("passionate", "dynamic", "synergistic", "results-driven").
4. **No Metric Fabrication**: Never invent numbers or proprietary metrics not grounded in provided source data.

---

## 📜 Execution Protocols

### 1. Header Standardization
Format every role or project header with clear, defensible seniority:
- Standard Format: `Senior Full-Stack Engineer | [Company / Client / Independent] | [Date Range]`
- Leadership Engagements: `Lead Full-Stack Engineer & Architect | [Company / Client] | [Date Range]`

### 2. Case Study 4-Part Structure
Format each project using this structured engineering breakdown:
- **Context & Scale**: Business domain, user volume, system scale, or legacy challenges.
- **Architectural Decisions**: Topology, decoupled/headless patterns, API design (REST/GraphQL), database schemas, and caching/indexing strategies.
- **Engineering Execution**: Concrete technical stack (PHP 8.x OOP, TypeScript, React, Docker, automated CI/CD, testing).
- **Measurable Impact**: Empirical business and performance outcomes (latency, throughput, technical debt reduction).

### 3. The Dutch Market Kill List
- **Remove Generic Adjectives**: Strip out "passionate", "dynamic", "guru", "rockstar".
- **Replace Generic Freelance Terms**: Convert "Freelancer" into "Contract Senior Software Engineer" or "Independent Technical Consultant".
- **Omit Irrelevant Domain Distractions**: Remove non-engineering side ventures to keep focus strictly on technical competence and system design.
